Locust 같은 부하 테스트 도구를 통한 시스템 차원의 Latency p95/QPS와 별개로, ANN(Approximate Nearest Neighbor) 알고리즘 단건 자체의 처리 성능 및 속도를 측정할 때 사용되는 대표적인 지표들을 정리해 드립니다.

1. 단건 처리(알고리즘 내부)에서 측정하는 대표 속도 지표
단건 쿼리가 입력되었을 때 통계적 지연시간 분포(p95, p99 등)를 보기 힘든 상태에서는 단일 연산에 소요되는 절대적 작업량이나 평균 시간을 측정합니다.

Query Latency (Mean / Median Latency, 단건 탐색 시간):

측정 방식: 단 1개의 쿼리 벡터가 주어졌을 때, 인덱스 그래프를 탐색하여 Top-K 결과를 반환하기까지 걸린 순수 시간(ms 또는 μs 단위).

특징: 부하가 없는 환경에서 수천~수만 개의 테스트 쿼리를 1개씩 단건(Single-thread)으로 순차 실행한 후, 그 평균(Mean)이나 중앙값(Median/p50)을 속도 지표로 사용합니다.

Distance Computations per Query (쿼리당 거리 계산 횟수):

측정 방식: 1회 검색 중 벡터 간 거리(L2, Cosine 등)를 총 몇 번 계산했는지 누적 횟수를 측정.

특징: 시간(ms) 지표는 측정하는 CPU 성능에 영향을 받지만, 거리 계산 횟수는 하드웨어 스펙과 무관한 알고리즘 고유의 순수 계산량이므로 학술적·이론적 속도 지표로 매우 선호됩니다.

Visited Nodes / Hops (방문 노드 및 홉 수):

HNSW 그래프 탐색 시 몇 개의 노드(벡터)를 거쳐 지나갔는지 나타내는 지표로, 탐색 알고리즘의 비효율성을 측정합니다.
